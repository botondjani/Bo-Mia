# tend

*Take care of you. Offline.* A screen-time companion for Android: you get a small free budget each day and earn the rest by doing real things. Bo or Mia, a small blob character, reflects how your day is going.

This is the MVP skeleton described in the concept doc. Native Android, English only, distributed as a side-loaded APK.

## Not done yet

- **Background Health Connect reads**: data is read only while tend is on screen (home or pause screen). The widget can lag until then.
- **Sleep starts counting from the first night after setup** (no credit for the night before installing).
- **Without a tracker**: when nothing writes sleep to Health Connect (or it isn't connected), last night's sleep is the longest screen-off stretch between 20:00 and noon, shown as "About … from your screen". "Workout or run" can always be started as a 30-minute timer with the screen fully off (60 s allowed for starting and a quick check); a tracker's workout counts too.
- **Step source**: Health Connect needs an app that writes steps (Google Fit, Samsung Health, Fitbit, or the phone's built-in step tracking on newer Pixels). Workouts count once a tracker writes an exercise session.
- Out of MVP scope (from the concept doc): floating character, friends, coins/shop, iOS.

## Build

Requires JDK 17+ and the Android SDK (platform 36). Start-up: Android 12+ shows Bo on sage as the splash, the installed-app list loads on a background thread, and the intro's feed animation draws without recomposing. Targets Android 16 (API 36); themed (monochrome) icon included. The APK contains ARM native code only (Rive), so it runs on phones but not on x86 emulators.

Two flavors: **sideload** (the APK testers install by hand) and **play** (the Google Play bundle: no direct battery-optimisation request, which Play allows only for a few kinds of apps). Release builds are signed with the upload key from `keystore.properties` (not in the repo; see `docs/play/store-listing.md`), or the debug key without it.

```bash
./gradlew testSideloadDebugUnitTest  # domain logic tests
./gradlew assembleSideloadRelease    # app/build/outputs/apk/sideload/release/app-sideload-release.apk
./gradlew bundlePlayRelease          # app/build/outputs/bundle/playRelease/app-play-release.aab
```

Google Play: listing texts, form answers (data safety, foreground service, Health Connect) and graphics are in `docs/play/`; the privacy policy page is `docs/privacy/index.html`. The landing page with the tester waitlist (Tally form) is `docs/index.html`; publish `docs/` with GitHub Pages (Settings → Pages → branch, folder `/docs`). `tools/store/` regenerates the store graphics and the Bo video clips (Rive web runtime + Playwright + ffmpeg).

## Test setup on the phone

Install the APK and follow the onboarding: Bo's four intro slides, companion, apps (installed social media apps are pre-selected; video and others are one tap away), activities, then two switches.

- **Display over other apps** comes first. Once it's on, Android lets tend bring itself back to the front after each switch.
- **Usage access** comes second.
- **Unlock first**: Android 13+ locks these switches for side-loaded apps ("restricted settings"), and the unlock option in App info only appears after Android has refused once. tend reads the lock state from the system (`android:access_restricted_settings` app op; falls back to the install source) and shows one step at a time: *Start* opens tend's own usage-access switch (tap, Android refuses, OK), then *Open App info* (⋮ → *Allow restricted settings*), then the two switches. Every system screen opens on tend's own switch or scrolled to it; tend comes back by itself where Android allows it, otherwise a note says the step is done and to press back. For testers using adb: `adb shell appops set app.tend ACCESS_RESTRICTED_SETTINGS allow`.
- **Health Connect** is connected from the home screen ("Connect Health Connect"). On Android 13 and below the button opens the Play Store to install it first.
- The reading timer keeps running when you leave tend. Opening a paused app from the pause screen ends it.
- **Limited mode**: "Continue without" skips the switches after explaining what stops working. Without usage access tend can't measure screen time (activities, timer and garden still work). Without the overlay there's no pause pop-up; minutes are still counted and a notification nudges instead (notification permission is asked for that). The home screen shows what's missing.
- **Next steps** (swipeable cards with dots; the widget card asks the launcher to place Bo and shows the guide if nothing appears within 5 s): 45 seconds after onboarding (and after the tour) a home card offers one step at a time: Health Connect first ("Got a smartwatch? Then sleep and workouts count too"), then the widget guide, until they're done or "Not now"; a week after "Not now" the important ones (keep awake, Health Connect) come back once. Settings has the widget button too; once placed, it shows a confirmation.
- Notification permission is otherwise asked only when you turn on the evening reminder. Until then the monitor's notification stays hidden.
- **Crash reports**: after a crash, the home screen offers "Share crash report" (stack trace, or a note when the Rive character's native code stopped the app). If Rive ever takes the app down, it switches itself off and the drawn character is used until a new APK is installed.
- On Xiaomi, Samsung, Huawei and similar phones, turn off battery optimisation for tend, or the monitor gets killed (this shows up in the miss log).
